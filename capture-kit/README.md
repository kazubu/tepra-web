# capture-kit — 公式ドライバ出力 (.prn) の採取・解析キット

公式 Windows ドライバが FILE: ポートへ出力する印刷ジョブ (.prn) を集め、
差分解析でジョブ内のバイトの意味を特定するためのキットです。
推測で実装すると実機で誤動作するため、新しいテープ幅やカット設定は
ここで採取したキャプチャを根拠にドライバへ反映します。

## 現状 (2026-11-15)

`1x/` と `2x/` に **SR3900P 公式ドライバ**のキャプチャが入っています
(テキスト "TEST 123"、9mm / 36mm × フルカット / ハーフカット / カットなし ×
1 枚 / 2 枚、および 4 / 6 / 12 / 18 / 24mm のハーフカット 1 枚)。
これらから次が確定し、ドライバに反映済みです
(`driver/docs/protocol.md` §2.3, §2.4, §2.6, §3):

| 項目 | 確定した内容 |
|---|---|
| ドット数 (全幅) | 4/6/9/12/18/24/36mm = 48/72/112/144/216/288/384 (= 幅mm × 12 を 8 の倍数に切り上げ、384 で頭打ち) |
| 補助バイト (offset 23) | 4mm = 18 (0x12)、6/9/12/18/24/36mm = 3/4/5/6/7/8 |
| カット | `C` コマンドの 4 パラメータ: full `03 01 01 01` / half `02 02 01 01` / none `00 00 00 00` |
| 枚数 | 1 ジョブ内で `L`/`T`/ラスタ/`0x0C` を枚数分繰り返す |
| 行ヘッダ | 幅フィールドは 16 ビット LE のドット数。固定バイトは SR3900P `00 0A 0A 01` (SR3700P は `00 0D 0D 01`) |
| 機種バイト | ヘッダ offset 9 = `0x68` (SR3700P `0x0E`)、版文字列 `"500"` (`"306"`) |

ドライバのテストは、これらのキャプチャ 12 本 (`driver/tests/fixtures/sr3900p-*.prn`)
をバイト単位で再現できることを確認しています。

`usbcap_9mm_half.pcapng` は SR3900P ドライバで 9mm ハーフカットを 1 枚
印刷したときの USBPcap キャプチャです。ここから「ヘッダブロックは USB に
流れない」「送信前に SOFT_RESET」「送信後は `C1 01` で状態ポーリング」が
分かり、印刷開始が 20 秒遅れる問題の修正根拠になりました
(`driver/docs/protocol.md` §1.6)。

### まだ足りないもの (優先順)

1. SR3700P を使う場合のみ: SR3700P ドライバでの 4 / 9 / 24 / 36mm
   (現在は推定値で警告付き)。
2. 50mm (使う予定があれば。テープ幅インデックス 7)。

pt → ドットの換算は、これらのキャプチャ (MS ゴシック 16pt) の文字
ピッチから校正済みです (`driver/docs/protocol.md` §4.2)。

## 1. Windows 側の準備

1. キングジム公式サイトから SR3900P 用の Windows ドライバをインストールする。
2. プリンタのプロパティ → ポート → **「FILE:」** (ローカルポートの
   「ファイルへ出力」) を選択して適用する。
   - 既存のポート設定は後で戻せるよう、変更前のポートをメモしておく。
3. 印刷に使うアプリケーション (公式のラベル作成ソフト、またはメモ帳でも可)
   で、採取条件をそろえる:
   - テキストは全ファイル共通で **`TEST 123`** に統一する。
   - フォントとサイズは全ファイルで固定する (例: ゴシック系フォント 24pt)。
     自動サイズは幅ごとに結果が変わって解析が難しくなるので使わない。
     **使ったフォント名とサイズをメモしておく** (pt 換算の校正に使う)。
   - 余白・カット以外の印刷設定 (印刷方向など) も全ファイルでそろえる。

## 2. 採取する組み合わせとファイル命名規則

テープ幅 × カット設定の組み合わせで印刷し、保存ダイアログで
下記の名前を付けて保存する (保存先フォルダは 1 つにまとめる)。

命名規則: **`w<幅mm>_<カット>.prn`**
カットは `full` (フルカット) / `half` (ハーフカット) / `none` (カットしない)。

今回欲しいもの: (現時点では特になし。上記「まだ足りないもの」参照)

注意:
- テープ幅はドライバの設定で切り替える (実テープは不要。FILE: 出力は
  設定値でジョブが生成される)。
- 同じ組み合わせを 2 回保存しない (取り直したら古い方を消す)。

## 3. 解析の回し方

```
python3 analyze_captures.py <採取フォルダ>
```

出力されるもの:
- ジョブ構造の一覧 (サイズ、幅バイト、補助バイト、ドット数、ビットマップ長、
  行数、余白、コピー数、カット (C パラメータ)、行ヘッダの固定バイト、版)
- 「カット設定だけが違うペア」「テープ幅だけが違うペア」の差分オフセット

既知のオフセット (スクリプト内 `KNOWN_OFFSETS` にも記載):
- offset 8: テープ幅バイト (mm そのまま)
- offset 9: 機種/ドライバ依存 (`0x0E` / `0x68`)
- offset 20: `12 + 4 × n` (n は文字数と思われていたが "TEST 123" で 5。要調査)
- offset 23: 補助バイト (6mm=3, 9mm=4, 12mm=5, 18mm=6, 36mm=8 実測、24mm=7 推定)
- offset 32: 意味不明のフラグ (公式ドライバ側でも 0/1 が揺れる)
- offset 2177: ヘッダのチェックサム
- offset 2183〜2186: `C` コマンドのパラメータ (カット)

`samples/` には本ドライバの `--dump` で生成したジョブ (SR3900P 設定の
全幅と `--cut half --copies 2`、SR3700P 設定の 18mm) が入っており、
スクリプトの動作確認と、キャプチャとの突き合わせに使えます。

## 4. キャプチャが返ってきたらやること

- [ ] `analyze_captures.py` を採取フォルダで実行し、出力を保存する
- [ ] 各幅のドット数 (行ヘッダの u16) と補助バイト (offset 23) を読む
- [ ] `driver/src/tepra/mod.rs` の `Tape::dots_with_source` で
      `(Model::Sr3900p, TapeWidth::MmN)` を `Captured` の実測値に置き換える
      (補助バイトが推定と違えば `TapeWidth::aux_byte` も)
- [ ] キャプチャを `driver/tests/fixtures/sr3900p-wN-full.prn` に置き、
      `builder.rs` の `rebuilds_sr3900p_*` に突き合わせテストを追加する
- [ ] `cargo test` 全通過、`server.py` / README / PATCH_NOTES の
      「フォールバック」記述を外す
- [ ] 実機 (SR3900P) で試験印刷して初めて「対応した」と言える

## 5. 成果物の返送方法

採取フォルダを zip にまとめて、このパッケージの管理者へ渡してください。
あわせて次のメモがあると解析が速くなります:

- 使ったドライバのバージョンと機種名
- フォント名とサイズ、カット設定の画面上の表記 (full/half/none との対応)
- 採取時に変えた設定があればその内容
