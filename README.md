# テプラ SR3900P Web 印刷パッケージ

Linux サーバに USB 接続したキングジム テプラ (SR3900P 想定) を、
他の PC のブラウザから使えるようにするための一式です。

構成:

- `driver/` — OSS ドライバ [tpsr3700](https://github.com/ruimo/tpsr3700)
  (SR3700P 向け) のフォーク。USB の Product ID を差し替え可能にし、
  Web 連携用に `--preview-out` (SVG をファイルに書き出して終了)、
  行ごとのサイズ比率 `--line-ratios`、装着テープ幅の取得
  `--detect-tape`、枠線 `--frame` を追加。さらに SR3900P 公式ドライバの
  キャプチャをもとに、機種切替 `--model sr3900p` (360 dpi)、9mm / 36mm、
  カット方式 `--cut`、枚数 `--copies` を追加。
  変更点の詳細は `PATCH_NOTES.md`。
- `server.py` — Python 標準ライブラリのみで動く Web アプリ (pip 不要)。
  テキストラベルのプレビュー (実寸表示つき) /印刷、テンプレート保存と
  書き出し/読み込み、差し込み印刷 (CSV / 系列リストの対応付け・
  組み合わせ、進捗表示とキャンセル対応)、印刷履歴と再印刷を提供。
- `capture-kit/` — Windows 公式ドライバの FILE: 出力 (.prn) を集めて
  解析するキット。`1x/` `2x/` に SR3900P ドライバの 4〜36mm 全幅
  (9mm / 36mm はカット 3 種 × 1枚/2枚) の FILE: キャプチャと、印刷 1 回分の
  USB キャプチャ (2026-11-15 採取) が入っており、テープ幅・カット・枚数・
  送信手順の根拠になっています (詳細は `capture-kit/README.md`)。
- `fonts/` — バンドルフォント BIZ UDPゴシック (`BIZUDPGothic-Regular.ttf`)。
  ライセンスは同梱の `OFL.txt` (SIL Open Font License 1.1)。
  好みのフォント (.ttf/.otf/.ttc) をここに置けば画面で選べます。

## 最初に読んでください (動作確認の状況)

実機での動作確認は、SR3900P とほぼ同スペック (360 dpi・384 ドットの
ヘッド、4〜36mm テープ、ハーフカット) の **テプラ PRO SR750** で行って
おり、`TEPRA_MODEL=sr3900p` の設定で問題なく印刷できています (9mm での
印刷開始・上下センタリング、フルカット / ハーフカット / カットなし、
枚数指定、差し込み印刷の 1 ジョブ送信)。ジョブ自体は SR3900P 公式
ドライバのキャプチャとバイト単位で一致させているため、SR3900P 本体でも
同様に動く見込みですが、SR3900P そのものでの印刷はまだ行っていません。
初めて使う機種では「実機での最初の確認手順」を一度通してください。

既知の制約:

- **USB の Product ID**: SR750 は SR3700P と同じ `0d8a:0103` だったので、
  ドライバ既定のままで動きます。他の機種では `lsusb` で実機の値を確認して
  `TEPRA_PID` に指定してください (下記)。
- **機種は `TEPRA_MODEL` で指定** (既定 `sr3900p`)。SR3700P は 270 dpi・
  192 ドット、SR3900P は 360 dpi・384 ドットで、テープ幅ごとに使う
  ドット数も異なります。
- **SR3900P のテープ幅は 4 / 6 / 9 / 12 / 18 / 24 / 36mm すべて**、
  SR3900P 公式ドライバのキャプチャと 1 バイト単位で一致することを
  テストで確認済みです。実機 (SR750) では 9mm で印刷を確認 (送信直後に
  印刷開始、文字は上下中央)。他の幅はまだ印刷していません。
- **カット方式 (フルカット / ハーフカット / カットしない) と枚数** は
  同キャプチャ由来で、実機 (SR750) で動作確認済みです。
- **SR3700P (`TEPRA_MODEL=sr3700p`) の 4 / 9 / 24 / 36mm は推定値**
  (上流キャプチャがあるのは 6 / 12 / 18mm のみ)。警告付きで印刷します。
- **解像度の換算を 208 dpi → 機種の実解像度に修正** したため、
  ラベル長・余白 (mm) の実寸は従来より変わります (SR3700P で約 1.3 倍、
  SR3900P で約 1.73 倍の行数)。**サイズ(pt) も公式アプリの pt と同じ
  大きさ**になるよう校正しました (キャプチャの文字ピッチから測定。
  `PATCH_NOTES.md` 8 節)。従来より同じ pt 指定で約 1.4 倍大きく出ます。
  なお pt は em (1 文字分の枠) の大きさを揃えるもので、同梱の BIZ UDP
  ゴシックは MS ゴシックより字面が大きいため、同じ pt でも大文字が
  1〜2 割背高に見えます (公式と完全に揃えたい場合は `fonts/` に
  MS ゴシックを置いて選択)。
- Web アプリに認証はありません。信頼できる LAN 内での利用を前提に
  してください。

## 前提

- Linux サーバ (ドライバのビルドに Rust ツールチェインが必要)
- Python 3.8 以降 (標準ライブラリのみ)
- プリンタを USB 接続し、`lsusb` コマンドが使えること

## インストール手順

### 1. ドライバのビルド

```sh
cd driver
cargo build --release
# できあがったバイナリを server.py と同じ場所に置く
cp target/release/tpsr3700 ../
cd ..
```

(生成バイナリは libusb を静的リンクするため、実行時に
libusb の共有ライブラリは不要です。)

### 2. USB Product ID を確認

プリンタを USB 接続して電源を入れ、サーバで実行:

```sh
lsusb
```

`ID 0d8a:xxxx` のような行 (キングジム製デバイス) を探し、
`xxxx` 部分が Product ID です。例: `Bus 001 Device 004: ID 0d8a:0103`
なら PID は `0103` です。SR750 は SR3700P と同じ `0103` でした
(ドライバ既定のため指定不要)。SR3900P など他の機種では値が違う可能性が
あるので、`lsusb` の表示と一致しているか確認してください。

### 3. udev ルールの設置 (一般ユーザで印刷するため)

同梱の `99-tepra.rules` の `idProduct` を手順2の値に書き換えて設置:

```sh
sudo cp 99-tepra.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules && sudo udevadm trigger
```

### 4. 動作確認 (まずドライバ単体で)

```sh
# テープ幅を指定すれば USB に触らずジョブ生成だけ確認できる
./tpsr3700 --tape-mm 18 --no-print --skip-preview --dump /tmp/job.prn "テスト"
./tpsr3700 --tape-mm 18 --preview-out /tmp/prev.svg "テスト"
# 行ごとのサイズ比率 (1行目を大きく、2行目を小さく)
./tpsr3700 --tape-mm 18 --preview-out /tmp/prev.svg --line-ratios 7,3 "HOST\n192.168.0.1"

# 実機確認: PID を指定して短いラベルを 1 枚
./tpsr3700 --pid <手順2の値> --skip-preview "テスト"
```

### 5. Web サーバの起動

```sh
TEPRA_PID=<手順2の値> python3 server.py
# ブラウザで http://<サーバのIP>:8090/ を開く
```

環境変数:

| 変数 | 意味 | 既定値 |
|---|---|---|
| `TEPRA_DRIVER` | ドライババイナリのパス | `./tpsr3700` (server.py と同じ場所) |
| `TEPRA_PID` / `TEPRA_VID` | USB ID (16進) | ドライバ既定 (0d8a:0103) |
| `TEPRA_MODEL` | 機種 `sr3900p` / `sr3700p` (解像度とテープ幅ごとのドット数、ジョブ内の機種バイト) | `sr3900p` |
| `TEPRA_PORT` | 待ち受けポート | 8090 |
| `TEPRA_DRY_RUN` | `1` で印刷の代わりにジョブ生成のみ | 無効 |
| `TEPRA_FAKE_TAPE` | 開発用モック: テープ幅取得が実機を問い合わせずこの mm 数を返す (UI 確認専用、印刷には影響しない) | 無効 |
| `TEPRA_TEMPLATES` | テンプレート保存先 JSON | `./templates.json` |
| `TEPRA_HISTORY` | 印刷履歴の保存先 JSON (直近100件) | `./history.json` |
| `TEPRA_FONTS_DIR` | フォント置き場 | `./fonts` |

常駐させる場合は同梱の `tepra-web.service` を環境に合わせて編集し、
`/etc/systemd/system/` に置いて `systemctl enable --now tepra-web`。

## 使い方

- **通常のラベル**: テキスト (改行可)、テープ幅、フォント、サイズ、
  配置、ラベル長を指定し、「プレビュー」で確認して「印刷」。
  プレビューは実際に印刷されるラスタから生成した SVG です。
  プレビューの下には実寸 (長さ × テープ幅) が表示され、プレビューの
  上辺には表示倍率に追随する mm 目盛りのルーラー (目安) が出ます。
- **枠線**: 「枠線を付ける」にチェックすると、印刷内容の周囲に枠を
  描きます。太さは 1〜3 ドットで指定でき、プレビューにもそのまま
  反映されます。複数行・サイズ比率・配置と組み合わせても使えます。
  テンプレート保存の対象にも含まれます。
- **プレースホルダ入りテキストのプレビュー**: テキストに `{{A}}` の
  ようなプレースホルダがあるとき、テキスト下の「プレビュー」は差し込み
  データの 1 件目 (CSV の最初のデータ行 / 各系列の 1 番目) で置き換えて
  表示します。値が無いプレースホルダがあれば、サーバへ送らずに画面で
  エラーを出します。プレースホルダが残ったまま「印刷」を押すと、
  置き換えずにその文字のまま印刷される旨を警告し、確認ダイアログで
  「そのまま印刷する」を選んだときだけ印刷します。
- **入力内容の保持**: ラベルの設定・テキスト・差し込み印刷の入力
  (CSV / 系列) はブラウザの localStorage に保存され、再読み込みしても
  そのまま残ります。「ラベルを初期設定に戻す」「差し込み印刷を初期設定に
  戻す」でそれぞれの欄だけを初期状態に戻せます (生成済みラベル一覧と
  プレビューは保存されないので、再読み込み後は再生成してください)。
- **履歴の読み込み**: 印刷履歴の「読み込む」で、その印刷の設定と
  テキストをフォームに戻して編集・プレビューできます (「再印刷」は
  そのまま印刷)。差し込み印刷の履歴は元の CSV / 系列を保存していない
  ため、設定と先頭ラベルだけを読み込みます。
- **装着テープの確認**: テープ幅の横の「装着テープを確認」ボタンで、
  本体に今何 mm のテープが入っているかを画面に表示します
  (ページ読み込み時にも自動で 1 回取得します)。ドライバの
  `--detect-tape` が本体へ問い合わせて返すもので、対応幅は
  印刷と同じ 6 / 9 / 12 / 18 / 24 / 36mm です。4mm や 50mm のテープが
  装着されている場合は、その幅であることは表示しますが
  「このドライバでは未対応の幅です」と注記します (印刷はできません)。
- **テープ送り**: 「テープを送る」(カットなし) と「送ってカット」(フル
  カット) で、指定長の空白テープを送れます (公式ドライバの「テープ送り」
  「テープ送り＆カット」相当)。送ってカットすると、ヘッド〜カッター間
  (約 9mm) が先頭の切れ端として別に出るため、切れ端＋指定長の 2 枚に
  なります (プリンタの仕様)。切れ端を出したくないときは「テープを送る」
  で送って手で切ってください。
- **ケーブル表示ラベル**: 「ケーブル表示ラベル」にチェックすると、テープ
  上端から測った印刷エリア内だけに印字します。既定は 24mm が 7.5mm、
  36mm が 12.5mm です (ラベルの公称値は 8mm / 13mm ですが、実機で試すと
  公称どおりでははみ出すため 0.5mm 控えています)。残りはケーブルに
  巻きつける透明部分として空けます。印刷ヘッドはテープの最外部
  (24mm で約 1.8mm、36mm で約 4.4mm) に届かないため、文字が入る高さは
  さらにその分狭くなります (24mm で約 5.5mm、36mm で約 7.9mm)。
  24mm / 36mm 以外のテープではエラーになります。合わないときは隣の
  「印刷エリア(mm)」で調整できます (空欄なら既定値)。
  テンプレートにも保存されます。
  なおケーブル用テープ (SV24K) は通常の 24mm テープと同じ値を本体に
  返すため、自動判別はできません。このチェックは手動で入れてください。
- **カットと枚数**: 「カット」(フルカット / ハーフカット / カットしない)
  と「枚数」(1 ジョブで同じラベルを複数枚、カット設定で切り分け) を
  指定できます。テンプレートにも保存されます。
- **余白**: 送り方向の余白を「なし (左1 / 右0)」「小 (左4 / 右3、既定)」
  「中 (左6 / 右5)」「大 (左8 / 右7)」「カスタム (左右を mm で入力)」から
  選べます。左が右より 1mm 大きいのは、SR3900P 実機で先端側が約 1mm
  短く出るのを補正するためです (上流の既定は左 10mm / 右 3mm でした)。
  テンプレートにも保存されます。
  なおテープ幅を「自動」にした場合、この確認とは別に、プレビュー/
  印刷の実行時にドライバがジョブごとに本体から幅を取得します。
- **行ごとのサイズ比率**: 複数行のテキストでは、行ごとに文字サイズの
  比率を指定できます。画面ではテキストの行数に合わせて比率の入力欄が
  自動で並びます (例: 2行で「7 : 3」)。長い行に横幅を引きずられず、
  見出し行を大きくするようなレイアウトに使えます。比率はテンプレート
  保存の対象にも含まれます。意味論は次節を参照してください。
- **テンプレート**: 現在の設定一式を名前を付けて保存し、呼び出せます。
  保存先はサーバ側の `templates.json` です。「テンプレートを書き出し」
  で全テンプレートを JSON ファイルとしてダウンロードでき、
  「ファイルから読み込む」で取り込めます。同名のテンプレートが
  ある場合は確認ダイアログが出て、「上書き」か「別名で追加
  (名前 (2) のように連番を付けます)」かを選べます。
- **差し込み印刷**: テキスト内の `{{A}}` `{{B}}` のような
  プレースホルダが置換対象です。プレースホルダ名には日本語も
  使えます (例: `{{名前}}`)。
  - CSV モード: 1行目をヘッダ (=プレースホルダ名) とする CSV を
    貼り付け/アップロードすると、行ごとに 1 枚印刷します。
    ファイルの文字コードは UTF-8 (BOM 付き含む) / Shift_JIS /
    EUC-JP を自動判定します (判定結果は画面に表示されます)。
    判定が外れた場合は「文字コード」欄で手動指定できます。
    Excel から出力した Shift_JIS の CSV もそのまま使えます。
  - 系列リスト モード: プレースホルダごとに値のリスト (1行1要素) を
    入力し、組み合わせ方を選びます。系列は「プレースホルダを検出」で
    テキストから作るほか、「系列を追加」ボタンで任意に追加できます
    (名前の変更・削除も可。追加した系列のプレースホルダはテキスト欄で
    使ってください)。系列は 3 つ以上でも使えます。
    - **対応付け**: インデックス同士を組にします。
      例: A=[aa,bb,cc], B=[1,2,3] → `aa 1` `bb 2` `cc 3` の 3 件。
      長さが違う系列があると短い方に合わせて切り詰め、画面に表示します。
    - **組み合わせ**: 全ての組み合わせを作ります。
      例: A=[aa,bb,cc], B=[1,2,3] → `aa 1` `aa 2` `aa 3` `bb 1` …
      の 9 件。マトリクス表は 2 系列の「組み合わせ」のときだけ
      表示され、3 系列以上では一覧表示のみになります。
  - 生成されたラベルは一覧からクリックで個別プレビューでき、
    「全ラベルを印刷」で **全ラベルを 1 ジョブにまとめて** 印刷します
    (ドライバの `--labels-file`。ジョブ内でラベルごとに L/T/ラスタの
    ブロックが並ぶ、公式ドライバの複数枚印刷と同じ構造)。そのため
    カット設定がラベル間にも効き、ハーフカットなら台紙がつながった
    1 本のテープになります。「枚数」は各ラベルに適用されます。
    キャンセルは送信前にのみ有効で、送信後はプリンタ側で最後まで
    印刷されます。複数行テンプレートでは行ごとのサイズ比率も
    そのまま効きます。
- **印刷履歴**: 単発印刷と差し込み連続印刷は、サーバ側の
  `history.json` に履歴として残ります (直近100件)。画面下部の
  「印刷履歴」から内容と結果 (成功/失敗・キャンセル) を確認でき、
  「再印刷」ボタンで同じ内容・同じ設定でもう一度印刷できます
  (失敗した印刷の再実行も同じ操作です)。「履歴を削除」で
  全件消去できます。
- **画面のテーマ**: OS のライト/ダーク設定に自動で追随します
  (ダークモード時はフォーム部品やスクロールバーも暗くなります)。
  テンプレートの削除は確認ダイアログが出ます。

## 行ごとのサイズ比率の意味論

ドライバの `--line-ratios "7,3"` (Web 画面の「行ごとのサイズ比率」) は、
`\n` で区切られた各行の文字サイズを比率で変えます。

- 比率の個数は行数と一致させてください。一致しない場合や 0 以下の
  値がある場合はエラーになります (黙って無視はしません)。
- 各行がテープ幅方向に占める帯 (バンド) も、比率に比例して
  分割されます。各行は自分の帯の中で上下中央に配置されます。
- サイズ自動時: 行 i のサイズは「そのテープ幅での最大サイズ ×
  r_i / 比率の合計」です。各行のフォント行高が自分の帯をちょうど
  埋める大きさになります。全て等比率 (1:1 など) の場合は、従来の
  「最大/行数・等分割」と同じ描画になります。
- `--size S` 明示時: S は「比率が最大の行」のサイズとなり、
  行 i は S × r_i / 最大比率 になります。どの行も S を超えないため、
  サイズ過大の警告は従来通り S に対して出ます。
- ラベル長 (`--max-tape-length-mm` / 画面のラベル長) と併用すると、
  ラベルはちょうどその長さになり、各行は余白の内側で「配置」に従って
  揃えられます。このとき折り返しはしません: 最も長い行が余白の内側に
  収まらない場合はエラーになります (テキストを短くする、サイズを下げる、
  ラベル長を伸ばす、のいずれかで対処)。比率が効くのは明示的な改行で
  区切られた行のみです。

## 実機での最初の確認手順

SR750 では下記の手順で問題なく動いています。SR3900P など初めての機種
では同じ順で確認してください。

1. `lsusb` で PID を確認 (上記手順2)。
2. 9mm か 12mm など、キャプチャのある幅のテープをセットする。
3. ドライバ単体で 1 枚だけ印刷 (上記手順4の3番目、`--model sr3900p`)。
   対話プレビューが出る場合は内容を確認して進める。
4. 印刷されたら、送信直後に印刷が始まること、文字の向き・上下位置・
   左右の余白・カット位置を確認する。うまくいかない場合は `--dump` で
   ジョブを保存し、テープ幅を変えて再試行するなど切り分ける。
5. Web 経由の印刷はドライバ単体で成功してから使う。

## ハーフカット・36mm・枚数について

SR3900P 公式ドライバのキャプチャ (`capture-kit/1x`, `2x`) の差分解析で
次が確定し、ドライバに反映済みです (`driver/docs/protocol.md` §2.3,
§2.6, §3)。

- カット方式は `C` コマンドの 4 パラメータ: フルカット `03 01 01 01`、
  ハーフカット `02 02 01 01`、カットなし `00 00 00 00`。
- 36mm はヘッダ補助バイト 8、ラスタ 1 行 384 ドット (ヘッド全幅)。
  9mm は補助バイト 4、112 ドット。ラスタ行のドット数は 16 ビット値
  (上流が 1 バイトと読んでいた「+8 ビット」はその上位バイト)。
- 複数枚は 1 ジョブ内で `L`/`T`/ラスタ/`0x0C` のブロックを枚数分繰り返す。
- SR3900P ドライバはラスタ行の固定バイトが `00 0A 0A 01` (SR3700P は
  `00 0D 0D 01`、3600/dpi と一致)、ヘッダ offset 9 が `0x68`、版文字列
  が `"500"`。`--model sr3900p` ではこれらを公式ドライバと同じ値にします。

ドライバのテストは、これらのキャプチャ (計 7 本) を 1 バイト単位で
再現できることを確認しています (ヘッダ offset 32 とチェックサムのみ除外。
offset 32 は公式ドライバ側でも揺れる意味不明のフラグ)。

その後 4 / 6 / 12 / 18 / 24mm のキャプチャも揃い、SR3900P の全幅が
確定しました (ドット数 = 幅mm × 12 を 8 の倍数に切り上げ、384 で頭打ち。
補助バイトは 4mm のみ 18 という例外値)。

## トラブルシュート

- **"TEPRA printer not found"**: プリンタの電源/USB 接続と、
  `--pid` (または `TEPRA_PID`) の値が `lsusb` の表示と一致しているか
  確認してください。エラーメッセージには実際に探した ID が出ます。
- **"Permission denied"**: udev ルールが設置・反映されているか確認。
  一時しのぎには root で実行する方法もあります。
- **テープ幅が違うと言われる / 自動判定がおかしい**: 明示的に
  テープ幅を指定 (`--tape-mm` / 画面のテープ幅) してください。
  SR3900P のテープ検出応答が SR3700P と異なる可能性があります。
- **ジョブを送ってから印刷開始まで 20 秒以上かかる**: 旧版は公式
  ドライバが送らないヘッダブロックまで送っていたためです (修正済み、
  `PATCH_NOTES.md` 7 節)。再発する場合は `--dump` と USBPcap で切り分け。
- **36mm などで期待通りに印刷されない**: ジョブは公式ドライバの
  キャプチャと一致しており、SR750 では 9mm で印刷を確認していますが、
  他の幅や SR3900P 本体では未確認です。`--dump` でジョブを保存して
  切り分けてください。
- **SR3700P で 4 / 9 / 24 / 36mm が正しく印刷できない**: SR3700P 用の
  キャプチャが無く、ドット数は推定です (warning が出ます)。SR3700P の
  Windows ドライバで `w<幅>_full.prn` を採取すれば確定できます。
- **プレビューは出るが印刷で化ける**: `--dump` のジョブを保存して
  切り分け材料にしてください。プロトコル差異の可能性があります。
